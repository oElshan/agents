# История изменений

## v2.1.0 — 2026-11-09

- Фича всегда реализуется через отдельные story-спеки под master; собственные AC и QA каждой story.
- Добавлены неизменяемые после approve specs, correction-шаблон и команда `/correction`.
- Markdown/wikilinks и spec/v1 frontmatter связывают иерархию, зависимости, блокеры и ресурсы.
- Оркестратор планирует независимые stories в worktree, интегрирует по одной и перепроверяет изменившуюся базу.
- Добавлены spec-graph, spec-plan, spec-effective и spec-scope; contract учитывает предков и prerequisites.
- Старые монолитные specs сохраняются при миграции. Для новых контрактов нужны G2 и approve.
- Обновлены агенты, board, QA, архитектура, профиль и инструкции оператора. Полный прогон
  нескольких агентов через OpenCode на реальном проекте остаётся отдельной проверкой.

### Обновление с 2.0

- Завершите активный запуск, сохраните локальные карточки и кэш, обновите пакет до v2.1.0.
- Старые монолитные спецификации сохраняются. Для активных фич создайте master и story-файлы
  с явным соответствием AC; повторите G2 и утверждение. Исторические вердикты не переносите автоматически.
- Настройте `orchestrator.parallel_stories` через `/setup` (новый профиль: 2; старый без поля: 1).
  Общий стенд остаётся последовательным до подтверждения его изоляции.
- `contract` продолжает читать legacy-specs; новые фичи используют spec/v1.

### Проверка и границы

63 теста прошли в исходном проекте, после чистой установки и после обновления subtree с v2.0.0.
При обновлении сохранены профиль, opencode.json, доска, кэш и локальное дополнение пакета.
OpenCode 2.2.5 загрузил все 10 проектных агентов. Полный цикл нескольких агентов, GitHub sync
и staging на реальном проекте не подтверждён. Worktree разделяет
рабочие каталоги, но не заменяет файловую песочницу; доской по-прежнему владеет один оркестратор.

## v2.0.0 — 2026-11-02

Версия добавляет исполняемые проверки качества и меняет формат профиля проекта.
Для обновления с 1.x нужна миграция настроек.

### Что изменилось

- Проверки SHA, снимка утверждённых документов, покрытия, миграций, health, логов и артефактов вынесены в Python CLI.
- Изменение тестов отменяет прежнее ревью. SHA кода отделён от SHA QA-отчёта.
- Покрытие проверяется по свежему JaCoCo XML. Пропущенный исходный файл блокирует результат.
- Liquibase XML master допускает подключение новой миграции без изменения существующих узлов.
- Пауза deploy сохраняет очередь. DevOps не меняет код после QA.
- Деплой связан с SHA кода и digest артефактов; G8 сверяет фактическое окружение.
- Утверждение связано со снимком требований, архитектуры, профиля и правил.
- GitHub sync учитывает все передаваемые поля. Добавлены правила восстановления после тайм-аута.
- Уточнены инженерные правила Spring, virtual threads и защиты от дублей.
- Добавлены 35 локальных тестов и GitHub Actions для Python 3.9 / 3.13.
- README переработан для продуктовых команд. Технические инструкции вынесены в руководство.

### Несовместимые изменения

- Нужны Python 3.9+ и Bash.
- `commands.backend.coverage_report` заменён на список `coverage_sources` с XML-отчётами.
- Staging требует `prepare_artifact`, `observe_artifact`, `status` и smoke.
- Для активных фич нужны новые `g2_snapshot` и `approved_snapshot`: повторите G2 и утверждение.
- Карточки получили поля версий QA/деплоя, исключения из декомпозиции и состояния GitHub sync.

[Переход на v2](.opencode/lib/README.md#обновление-существующего-проекта).

### Проверка и границы

35 тестов прошли локально и после установки пакета. Проверены установка с нуля и обновление
subtree с v1.0.2 с сохранением локальных настроек и доски. OpenCode 2.0.29 загрузил все 10 проектных агентов.
Полный цикл агентов, GitHub sync и staging с новыми проверками пока не подтверждён.
Файловая изоляция и транзакционное состояние доски не входят в эту версию.
