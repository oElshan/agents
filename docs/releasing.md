# Выпуск версии

Исходный проект хранится в `main` и `develop`. Пакет для установки — содержимое `.opencode`.
Ветка `dist` и теги `v*` указывают на историю этого пакета, а не на корень исходного проекта.
Поэтому тег можно подключать через `git subtree add --prefix=.opencode`.

## Порядок

1. Получите актуальные ветки и теги. Проверьте отсутствие чужих незакоммиченных изменений.
2. Обновите README, CHANGELOG и инструкции миграции.
3. Выполните тесты и `git diff --check`. Проверьте загрузку проектных агентов в OpenCode.
4. Закоммитьте изменения. Синхронизируйте `develop` и `main` обычным fast-forward или merge.
5. Создайте пакет: `git subtree split --prefix=.opencode main`. Сохраните полученный SHA.
6. Проверьте установку пакета в новый репозиторий и обновление с предыдущего тега.
7. Создайте аннотированный тег на SHA пакета. Не перемещайте опубликованные теги.
8. Опубликуйте `main`, `develop`, `dist` и тег. По возможности используйте атомарный push.
9. Создайте GitHub Release с изменениями, порядком обновления и границами проверки.
10. Проверьте удалённые SHA и результаты CI.

## Проверки

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s .opencode/tests -v
git diff --check
opencode debug agents
```

Ожидаются 10 проектных агентов. OpenCode может показать также встроенных агентов.
Автотесты CLI не заменяют полный прогон `/setup` → `/feature` → `/approve` → draft PR.
Если полный прогон не выполнен, укажите это в release notes.

Major-версия меняет совместимость профиля, карточек или процесса обновления.
Minor добавляет совместимые возможности. Patch исправляет ошибки без смены формата.

CI находится в корне исходного репозитория и не входит в пакет `dist`.
